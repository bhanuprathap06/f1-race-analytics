🚀 START PRODUCTION SERVER
─────────────────────────────────────────────────────────────────────────────

Option 1: Using startup script (easiest)
  bash start_production.sh

Option 2: Manual Gunicorn
  python3 -m gunicorn -w 4 -b 0.0.0.0:8000 --timeout 120 api_server:app

  python3 -m gunicorn -c gunicorn_config.py api_server:app

Option 4: Docker container
  docker build -t f1-ml-api .
  docker run -p 8000:8000 f1-ml-api

Option 5: Docker Compose (API + Dashboard)
  docker-compose up -d

🔧 COMMON GUNICORN OPTIONS
─────────────────────────────────────────────────────────────────────────────

-w 4              → Number of workers (4 = good for 4-core CPU)
-b 0.0.0.0:8000   → Bind address and port
--timeout 120     → Worker timeout in seconds (important for ML models)
--max-requests 1000 → Reload workers after N requests (memory management)
--access-logfile - → Log access to stdout (use "-" for stdout)
--error-logfile -  → Log errors to stdout
-c config.py      → Use config file

Examples:
  # Fast & lightweight
  python3 -m gunicorn -w 2 -b 0.0.0.0:8000 api_server:app

  # High concurrency
  python3 -m gunicorn -w 8 -b 0.0.0.0:8000 api_server:app

  # With logging
  python3 -m gunicorn -w 4 -b 0.0.0.0:8000 \
    --access-logfile logs/access.log \
    --error-logfile logs/error.log \
    api_server:app


🔍 MONITORING
─────────────────────────────────────────────────────────────────────────────

Check if running:
  curl http://localhost:8000/api/stats

View worker processes:
  ps aux | grep gunicorn

Check memory usage:
  ps aux | grep gunicorn | awk '{print $6}' | tail -n +2 | awk '{sum+=$1} END {print "Total: " sum "KB"}'

Monitor requests in real-time:
  tail -f logs/gunicorn-access.log

View errors:
  tail -f logs/gunicorn-error.log


🛑 STOP SERVICES
─────────────────────────────────────────────────────────────────────────────

Kill Gunicorn:
  pkill -f gunicorn

Kill by port:
  lsof -i :8000 | grep LISTEN | awk '{print $2}' | xargs kill -9

Kill with signal:
  kill -TERM $(pgrep -f gunicorn)  # Graceful shutdown
  kill -QUIT $(pgrep -f gunicorn)  # Quit workers


⚙️  WORKER CONFIGURATION
─────────────────────────────────────────────────────────────────────────────

Recommended worker count = (2 × CPU_cores) + 1

CPU Cores  →  Workers
1             3
2             5
4             9
8             17

Worker types:
  sync       → Best for CPU-bound (default) [ML predictions]
  async      → Best for I/O-bound [databases]
  gevent     → Best for high concurrency [WebSockets]
  tornado    → Best for WebSockets

💡 PERFORMANCE TUNING
─────────────────────────────────────────────────────────────────────────────

Slow responses?
  → Increase timeout: --timeout 240
  → Add more workers: -w 8

High memory?
  → Reduce workers: -w 2
  → Enable recycling: --max-requests 500

Connection errors?
  → Increase backlog: --backlog 2048
  → Check port: lsof -i :8000

Model training slow?
  → Increase timeout: --timeout 300
  → Single worker: -w 1 (for testing)
